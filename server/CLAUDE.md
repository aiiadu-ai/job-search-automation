# jobs — генератор резюме й супровідних листів

Власниця — Аія, не програмістка, вчиться вайбкодингу. Пояснюй простими словами українською,
питай перед `sudo`, перед встановленням пакетів і перед зміною crontab.
**Не чіпай** tmux-сесію `bot`, папку `~/bot` і службу бота — це окремий проєкт.

## Що робить
По буднях о 9:00 (Київ) скрипт:
1. Забирає з n8n чергу вакансій, на яких Аія натиснула «✉️ Зробити чернетку».
2. Для кожної вакансії через `claude -p` генерує вміст резюме + супровідний лист.
3. Підставляє вміст у `resume-template.html`, рендерить PDF headless-Chromium'ом.
4. Відправляє PDF + лист назад у n8n. n8n сам створює чернетку Gmail і шле PDF у Telegram.

## Файли в цій папці
- `resume-template.html` — шаблон резюме (дизайн v4, A4, 1 сторінка). Плейсхолдери й формат
  HTML для кожного описані в коментарі на початку файлу: `{{HEADLINE}} {{SUMMARY}} {{SKILLS}}
  {{EXPERIENCE}} {{PROJECTS}} {{EARLIER}}`. Решту шаблону не змінювати.
- `photo.jpg` — фото, шаблон бере його відносним шляхом, тому HTML рендерити з цієї ж папки.
- `resume-base.md` — **єдине джерело фактів** + правила генерації. Нічого поза ним не вигадувати.
- `.env` — `N8N_BASE` і `JOBS_KEY`. Ключ секретний: не друкувати в логи, не комітити.

## API n8n (ключ у заголовку `x-jobs-key: $JOBS_KEY`)
**Черга:** `GET $N8N_BASE/webhook/jobs-queue` →
```json
{ "count": 1, "jobs": [ { "id": 6, "kind": "direct|vacancy", "source": "Djinni", "title": "...",
  "company": "...", "link": "...", "chat_link": "...", "recruiter": "...", "recruiter_email": "",
  "received_at": "2026-10-27T13:20:05.000Z", "fit": "green|yellow", "text": "текст вакансії/листа" } ] }
```
Неправильний ключ → порожня відповідь (не JSON). Це помилка, не «порожня черга».

**Готово:** `POST $N8N_BASE/webhook/jobs-done`, `Content-Type: application/json`:
```json
{ "id": 6, "title": "...", "company": "...", "to": "email або порожньо", "chat_link": "...",
  "subject": "тема листа", "letter": "текст листа (plain text)",
  "filename": "Anastasiia_Ukrainska_Resume_<Company>.pdf", "pdf_base64": "..." }
```
Відповідь `{"ok":true,"id":6}` = чернетка створена, n8n сам ставить вакансії статус `drafted`
(вдруге вона в черзі не з'явиться). Якщо не `ok` — вакансія лишається в черзі на наступний раз.
- `to` = `recruiter_email`, якщо є. Для Djinni (є `chat_link`, нема email) — `to` порожній.

## Генерація (`claude -p`)
- Одна вакансія = один виклик. Дай Claude `resume-base.md` + дані вакансії, попроси **лише JSON**:
  `headline, summary, skills, experience, projects, earlier` (HTML-фрагменти за форматом із
  шаблону) + `lang` ("uk"/"en"), `subject`, `letter`.
- Правила з `resume-base.md` обов'язкові: резюме англійською, лист мовою вакансії, 120–180 слів,
  без вигаданих фактів, цифри в `<em>`, проєкти з позначкою ⛔ не брати.
- Якщо `kind = direct` (рекрутер написав першим) — лист починається з контексту: хто писав,
  де (Djinni / пошта) і що Аія відповідає зі своєї основної пошти you@example.com.
- Заголовок вакансії чистити від сміття типу «(Direct message)».
- Перевір JSON (всі поля є, не порожні). Якщо зламаний — один повтор, далі пропусти вакансію.

## PDF
- Chromium headless `--print-to-pdf`, без колонтитулів, фон увімкнений; шрифт Inter вантажиться
  з Google Fonts — дочекатися завантаження (або вбудувати шрифт локально).
- **Рівно 1 сторінка.** Перевір кількість сторінок (напр. `pdfinfo`). Якщо 2 — попроси Claude
  скоротити (менше пунктів, прибрати EARLIER) і відрендерь ще раз.

## Запуск і розклад
- `./run.sh` — бойовий запуск; `./run.sh --dry-run` — все те саме, але PDF і лист лише
  зберігаються в `out/`, у n8n нічого не відправляється. Спершу завжди dry-run.
- Лог кожного запуску в `logs/` (дата, які вакансії, успіх/помилка), без ключа.
- Розклад: crontab користувача, `CRON_TZ=Europe/Kyiv`, `0 9 * * 1-5`.
- Скрипт не повинен падати повністю через одну погану вакансію: помилка → в лог → наступна.
